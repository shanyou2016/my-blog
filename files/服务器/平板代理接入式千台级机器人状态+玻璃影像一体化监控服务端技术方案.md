> 适用场景：机器人本地直连平板 App，平板通过 4G 网络统一接入服务端，同步承载**MAVLink 实时运行数据透传**与**玻璃巡检高清图片采集**，支持千台级设备并发、单栋楼千张级玻璃影像归档
> 设计基准：核心 MAVLink 链路与 Android 平板端架构**同源设计**，影像链路独立于实时信令链路，大小流分离、存算分离，兼顾实时性、可靠性与海量影像承载能力

## 一、端到端部署拓扑

```Plain Text
机器人设备（本地MAVLink协议 + 相机采集）
        ↓ 本地WiFi/直连
平板App（边缘代理：本地控制 + 实时数据聚合 + 玻璃图片拍摄 + 4G双链路上行）
        ├─ MQTT over 4G ── 小消息实时链路 ──┐
        └─ HTTP over 4G ── 大文件影像链路 ──┤
                                                  ↓
服务端  ┌─ 接入网关层 → 协议解析层 → 统一状态层 → 监控业务层
        └─ 对象存储 ←──────────────────────────┘
```

- **双链路分离**：MAVLink 实时数据、平板状态走 MQTT 小消息链路；玻璃高清图片走 HTTP 大文件链路，互不阻塞、独立扩容

- 服务端不直接承载图片文件，图片由平板直传对象存储，服务端仅管理元数据与访问索引

- 下行：控制指令、巡检任务通过 MQTT 下发至平板，再由平板转发机器人或触发拍摄

## 二、核心设计原则（开发强制遵循）

**保留原有 6 项基础原则，新增 2 项影像专项原则**

1. **双端同源原则**：MAVLink 协议、状态模型、心跳策略、设计模式与平板端完全对齐

2. **两级状态原则**：平板终端链路状态、机器人设备状态分层独立建模，故障精准定位

3. **轻量高并发原则**：全局共享管理器 \+ 轻量终端上下文，批量调度支撑千台级并发

4. **单向数据流原则**：数据从接入到输出严格单向流动，状态唯一入口

5. **故障隔离原则**：单终端异常自动熔断，故障不扩散；状态防抖避免网络抖动误判

6. **插件化扩展原则**：各层能力插件化扩展，不侵入核心主链路

7. **大小流分离原则**：实时信令与影像文件独立链路、独立线程池、独立限流，避免大流量阻塞实时业务

8. **存算分离原则**：图片文件与元数据分离存储，图片处理异步化，不占用主链路资源

## 四、核心模块详细设计

### 4\.1 接入网关层（双链路独立设计）

#### 4\.1\.1 MQTT 信令接入（原有能力完全保留）

- 基于 MQTT Broker 实现大规模平板终端接入，适配 4G 弱网，支持 QoS 0/1 分级

- 平板 SN 唯一标识鉴权，建立平板 ID 与绑定机器人 ID 映射

- 内置指数退避重连、单终端限流、积压自动熔断机制

- **线程约束**：MQTT IO 线程仅做消息收发，业务逻辑提交业务线程池

#### 4\.1\.2 HTTP 图片接入网关（新增影像能力）

- 独立 HTTP 接口，与 MQTT 端口、线程池完全隔离，避免大文件传输阻塞实时信令

- 核心能力：

    1. 上传鉴权：基于设备令牌 \+ 任务 ID 校验，非法设备拒绝接入

    2. 断点续传：支持分片上传、断点恢复，适配 4G 网络波动中断场景

    3. 并发限流：单平板同时上传数≤3，全局并发上传数可配置，避免瞬时打满带宽

    4. 直传对象存储：支持服务端中转或平板直传对象存储两种模式，推荐直传模式，服务端仅做签名与回调

- **溢出策略**：上传队列满时拒绝新请求并告知平板延后重试，优先保障正在进行的上传完成

### 4\.2 协议解析层

#### 4\.2\.1 MAVLink 与平板状态解析（原有能力完全保留）

- MAVLink 编解码逻辑与平板端 100% 同源，帧校验、消息识别、字段提取完全一致

- 平板终端状态数据解析，插件化扩展，不侵入主链路

#### 4\.2\.2 图片元数据解析（新增）

- 解析上传回调中的图片元数据：图片 ID、楼栋 ID、玻璃 ID、拍摄时间、分辨率、文件大小、拍摄位置

- 校验元数据完整性，关联对应机器人与巡检任务，异常数据直接丢弃并记录

- 解析逻辑轻量，仅做字段校验与结构化，不做图片内容处理

### 4\.3 统一状态层（核心：双状态 \+ 影像扩展）

#### 4\.3\.1 两级终端状态（原有能力完全保留）

1. **平板终端状态**：CONNECTED/UNSTABLE/DISCONNECTED，基于 MQTT 连接心跳 \+ 消息活跃度判定

2. **机器人设备状态**：ONLINE/WARNING/OFFLINE，基于 MAVLink 数据更新频率判定

3. **批量心跳管理器**：全局单线程每秒批量巡检，策略、阈值、防抖机制与平板端完全对齐

#### 4\.3\.2 巡检任务与影像状态管理器（新增）

- 巡检任务生命周期管理：下发→进行中→已完成→异常，全程跟踪进度

- 图片元数据索引：按楼栋、玻璃、时间、机器人多维度建立索引，支持快速检索

- 状态推导原则：与原有状态模型一致，任务进度由上报图片数量计算得出，禁止直接赋值

### 4\.4 监控业务层

#### 4\.4\.1 基础监控业务（原有能力完全保留）

- 集中状态 API、统一告警中心、数据持久化、北向透传

#### 4\.4\.2 影像专项业务（新增）

- 影像查询 API：支持按楼栋、玻璃编号、时间范围、机器人 ID 多维度查询

- 缩略图服务：异步生成缩略图，列表页默认返回缩略图，详情页按需加载原图

- 巡检任务管理：创建、下发、暂停巡检任务，查看任务进度与完成率

- 归档管理：按巡检批次、楼栋周期归档，支持历史版本回看

### 4\.5 基础设施层

- 模块生命周期：启动顺序与平板端对齐：日志→MQTT 接入→HTTP 接入→协议解析→状态管理→业务

```Plain Text

    ↓
```

## 八、开发参考规范（强制约束）

**原有 6 项规范保留，新增 3 项影像专项规范**

1. **模块启停规范**：所有管理器继承 AbstractManager，遵循幂等启停；启动顺序与平板端对齐

2. **状态推导规范**：所有状态由上下文字段计算得出，禁止直接赋值

3. **线程隔离规范**：IO 线程只做 IO，业务逻辑提交线程池；心跳调度线程禁止耗时操作

4. **状态写入规范**：状态变更唯一入口为统一状态层，其他层不得直接修改

5. **日志规范**：日志级别、格式、关键字与平板端对齐；关键路径必须埋点

6. **扩展规范**：新增能力插件化扩展，不得修改核心状态层与主链路逻辑

7. **大小流分离规范**：图片传输必须走独立 HTTP 链路，禁止通过 MQTT 传输大图；图片处理必须走独立线程池

8. **存算分离规范**：图片文件必须存对象存储，服务端只存元数据；图片处理必须异步，禁止阻塞主链路

9. **元数据校验规范**：图片元数据必须校验完整性与合法性，异常数据直接丢弃，不污染状态层
